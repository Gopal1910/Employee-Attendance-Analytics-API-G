# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–38) | Timezone mismatch and premature floor division: `punch_in.replace(hour=h, minute=m)` replaces hours on UTC timestamps instead of IST, causing a 5.5-hour offset. Evaluating `minutes > 10` after integer floor division returns 0 for elapsed times between 10:01 and 10:59 (e.g. 09:40:30 gives 0 instead of 10). | Punch-in at 09:40:30 for a 09:30 shift returns `late_minutes = 0` instead of `10`. Comparing UTC BSON datetimes produces negative or invalid elapsed times. | Truncated instant to whole seconds, converted to IST timezone, compared elapsed seconds strictly against 600 seconds (10 min grace period), and calculated `int(diff_seconds // 60)` when late. |
| 2 | `compute_work_hours` (lines 40–42) | Uses Python's built-in `round()`, which applies banker's rounding (round-half-to-even) rather than the contractually required decimal half-up rounding (R4). Also fails to truncate instants to whole seconds. | `compute_work_hours` on 7,650 seconds (2.125 hours) produces `2.12` instead of `2.13`. | Truncated instants to whole seconds, computed elapsed hours using `Decimal`, and quantized with `ROUND_HALF_UP` to two decimal places. |
| 3 | `compute_overtime` (lines 44–48) | Ignores the R3 minimum 30-minute threshold and fails overnight shifts: calculates elapsed minutes without checking `minutes >= 30` and anchors `shift_end` to the shift start date (`date_str`) rather than the following calendar day for overnight shifts (`shift_end <= shift_start`). | Punching out 15 minutes after shift end returns 15 instead of 0. For an overnight shift (22:00–06:00), overtime is computed as thousands of minutes. | Anchored `shift_end` to `date + 1 day` when `shift_end <= shift_start`, computed elapsed whole minutes, and returned minutes only when `>= 30`, otherwise `0`. |
| 4 | `GET /health` (lines 72–74) | Returns HTTP 200 `{"status": "ok"}` unconditionally without checking MongoDB connectivity. Contract requires 200 only if MongoDB responds to a ping, otherwise 503. | Stopping MongoDB or providing an invalid `MONGO_URI` still causes `/health` to return 200 OK instead of 503 Service Unavailable. | Added `client.admin.command("ping")` within a try/except block; raises `HTTPException(503, "Database unavailable")` if the ping fails. |
| 5 | `POST /employees` (lines 78–85) | Check-then-insert race condition (`find_one` then `insert_one`), unhandled 500 error on duplicate keys, storing local naive `datetime.now()`, returning datetime object instead of epoch milliseconds integer, and missing schema validation (allowing equal shift start/end and invalid formats). | Concurrent creates crash with 500. `created_at` in the API response is an ISO string instead of integer epoch milliseconds. Creating with `shift_start == shift_end` succeeds instead of returning 422. | Enforced database unique index on `emp_code`, caught `DuplicateKeyError` returning 409, validated Pydantic model (`shift_start != shift_end`, regexes), stored UTC datetime, and returned `created_at` as integer epoch milliseconds. |
| 6 | `GET /employees` (lines 88–96) | Broken pagination offset `skip = page * page_size`, total count ignores department filter (`count_documents({})`), missing sorting by `emp_code` ascending, and unvalidated pagination bounds. | Requesting `page=1` skips the first 20 records. Filtering by department returns the global headcount as `total`. Employees return in arbitrary order. | Set `skip = (page - 1) * page_size`, counted filtered documents `db.employees.count_documents(q)`, added `.sort("emp_code", 1)`, and added query parameter constraints (`page >= 1`, `1 <= page_size <= 100`). |
| 7 | `POST /attendance/punch-in` (line 101) | Missing employee existence check: if `find_one` returns `None`, accessing `emp["shift_start"]` raises `TypeError: 'NoneType' object is not subscriptable` resulting in an unhandled HTTP 500 instead of HTTP 404. | Calling punch-in with a non-existent `emp_code` returns HTTP 500 Internal Server Error. | Checked `if not emp: raise HTTPException(404, "Employee not found")`. |
| 8 | `POST /attendance/punch-in` (lines 102–103) | Attendance date calculation uses local system clock (`datetime.fromtimestamp(...)`), completely ignores IST (UTC+05:30), and fails overnight shift date assignment where punch-in before `shift_end` belongs to the previous calendar day (R1). | Overnight shift worker punching in at 01:00 IST for a 22:00–06:00 shift gets the current date rather than the previous date when the shift began. | Implemented `calculate_attendance_date` in IST, accounting for overnight shift boundary transitions and whole-second instant truncation. |
| 9 | `POST /attendance/punch-in` (lines 104–105, 118) | Check-then-insert race condition: `if db.attendance_logs.find_one(...): raise HTTPException(409)` allows concurrent requests arriving at the same millisecond to both pass `find_one` and attempt insertion, causing duplicate records or unhandled 500 errors. | Firing concurrent punch-in requests for the same employee and date crashes or creates duplicates. | Created compound unique index on `(emp_code, date)` and wrapped `insert_one` in try/except catching `DuplicateKeyError` to return HTTP 409 cleanly. |
| 10 | `POST /attendance/punch-in` (lines 119–121) | Leaks internal MongoDB ID: sets `doc["id"] = str(res.inserted_id)`. The OpenAPI contract and `DATA_MODEL.md` explicitly prohibit `_id` and `id` in requests and responses. Also returns datetime object for `punch_in` instead of integer epoch milliseconds. | Response body contains illegal `"id": "..."` field and unformatted timestamp, failing schema validation against `AttendanceRecord`. | Removed `_id` and `id` from response and formatted `punch_in` as integer epoch milliseconds. |
| 11 | `POST /attendance/punch-in` (lines 63–67) | Missing validation for `punched_at` and `status`: permits invalid statuses (e.g. `ABSENT`, `LEAVE`, arbitrary strings) and allows non-epoch-millisecond numbers (such as seconds or negative numbers). | Supplying `punched_at: 1700000000` (seconds) or `status: "LEAVE"` succeeds with 201 instead of returning 422. | Enforced Pydantic constraints: `punched_at` must be between 100000000000 and 4102444800000, and `status` restricted to `PRESENT`, `WFH`, `ON_DUTY`. |
| 12 | `GET /attendance` (lines 144–147) | Catastrophic in-memory loading and sorting: executes `list(db.attendance_logs.find(q))` loading the entire collection into Python memory and sorting via Python's `sort()`. | 14 | `GET /attendance` (lines 137–141) | Missing date range validation: does not check if `date_from > date_to`. If inverted dates are supplied, it returns an empty list with 200 OK instead of the required HTTP 422. | Requesting `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returns 200 OK instead of 422. | Added validation `if date_from and date_to and date_from > date_to: raise HTTPException(422, "date_from must be <= date_to")`. |
| 15 | Startup Configuration (lines 20–24) | No index creation on startup: the starter creates zero indexes, causing all queries to perform full collection scans (`COLLSCAN`) and leaving unique constraints unenforced at the database level. | Inspecting execution plans with `explain("executionStats")` shows `COLLSCAN` on all queries. | Added idempotent index creation in FastAPI `lifespan` handler covering all queries and constraints. |

## Examined and Confirmed as Correct

- **PyMongo Synchronous Driver in FastAPI**: The use of PyMongo's synchronous client rather than Motor was evaluated. FastAPI automatically executes synchronous route handler functions in an external AnyIO threadpool worker thread, preventing event loop starvation. PyMongo provides reliable connection pooling, BSON serialization, and complete aggregation pipeline support without asynchronous driver overhead.
- **Natural Business Key (`emp_code`, `date`)**: Addressing attendance records by `(emp_code, date)` without synthetic IDs was verified against `DATA_MODEL.md`. This natural composite key ensures idempotency, aligns with HR business semantics, and is reliably enforced via MongoDB compound unique indexing.
